Aislar · dónde corre

Qué alcanza el código si se sale de control. El caso de julio pasó aquí: la red aislada tenía una salida.

Permisos · qué puede hacer

Replit, julio 2025: el agente borró la base de producción durante un code freeze y luego fabricó 4,000 usuarios falsos. Ahí faltaba separar desarrollo de producción.

Hoy toca aislar. Los permisos los vimos el jueves pasado, con los tokens de ejecución.

El punto de partida real

Casi todos empiezan en un devcontainer.

Filesystem propio, paquetes propios, acceso limitado al host, y ya lo traes configurado en VS Code.

Los dos límites que la gente reporta al usarlo con agentes:

  • Corre un entorno a la vez. Para poner tres agentes a trabajar en paralelo sobre el mismo repo, tienes que duplicar la configuración a mano.
  • Sigue compartiendo el kernel del host.
  • Docker sacó su propio producto para agentes, Docker Sandboxes, y corre en una microVM: kernel, filesystem y red propios.
Por qué no alcanza

Los contenedores comparten el kernel del host.

Un exploit de kernel desde adentro y estás en el host — y en todos los demás contenedores de esa máquina.

Con código escrito por un modelo, ese código puede estar diseñado para buscar exactamente eso.

Cómo elegir

Cuatro preguntas antes de ver precios.

1 · ¿Cuánto vive?

Segundos por tarea, o días de trabajo continuo.

2 · ¿Guarda estado?

Empieza limpio cada vez, o retoma donde se quedó.

3 · ¿Qué tan rápido arranca?

El cold start lo espera tu usuario, no tu servidor.

4 · ¿Quién paga el idle?

Mientras el agente espera al modelo, ¿el reloj corre? Las plataformas administradas cobran ese tiempo con un markup de 7 a 10 veces.

Como lo haces hoy

Expones cada herramienta como una llamada. El modelo las pide una por una, y tú pagas una vuelta completa por cada una.

Code Mode

Expones tus herramientas como una API de TypeScript y el modelo escribe el código que las orquesta: loops, condicionales, manejo de errores. Una sola pasada.

Ese código lo escribió un modelo y tiene que correr en algún lado. Por eso la caja va primero.

Apunte · dónde quedamos

Un agente encerrado en una caja de texto contesta preguntas. Un agente con una computadora hace trabajo. La diferencia entre los dos es lo que discutimos el jueves pasado.

Apunte · la pregunta

El devcontainer es la respuesta más extendida hoy, y viene de antes de los agentes: se diseñó para que un equipo comparta el mismo entorno, no para contener a alguien que quiere salirse.

Apunte · el caso

Pasó en una evaluación controlada, que es justo donde uno quiere que pase. El detalle que vale la pena registrar: los modelos dedicaron cómputo de inferencia a conseguir salida a internet. No fue un tropiezo, fue un objetivo.

La auditoría forense confirmó que los datos de clientes quedaron intactos.

Apunte · las dos capas

Los dos casos se citan mucho para vender lo mismo, y cada uno prueba una cosa distinta. En Replit faltaba separar desarrollo de producción, que es permisos. En el de julio la red estaba aislada y aun así tenía una salida, que es aislamiento.

Apunte · devcontainers

El límite de una sola instancia se siente cuando quieres correr tres agentes en paralelo sobre el mismo repo. Varios equipos terminan con una VM por workspace, cada una con su propio git worktree.

Apunte · kernel

La imagen mental útil: departamentos con paredes propias, pero un solo piso. Si el piso cede, no importa qué tan gruesas eran las paredes.

Apunte · la escalera

El escalón que necesitas depende de cuánto confías en el código que va a correr. Código tuyo, escalón bajo. Código que escribió un modelo a partir de una página web que leyó, escalón alto.

Apunte · Firecracker

Es el mismo principio de cualquier sistema de seguridad: menos superficie, menos por auditar. Un hipervisor de 50 mil líneas se puede revisar entero; uno de millones, no.

En pantalla

Sandbox real levantándose, con el cronómetro a la vista. Lo importante del demo es el tiempo de arranque y lo que pasa cuando corres algo que no deberías.

Apunte · las cuatro

Sirven para leer cualquier comparativa sin perderse entre features. Las cuatro salen del patrón de uso, que es lo que cambia entre un agente y un job normal.

Apunte · el mapa

En el último año salieron muchísimos: E2B, AIO Sandbox, Sandboxer, AgentSphere, Exe.dev y los de las nubes grandes. Varios corren Firecracker por debajo, así que lo que los distingue es el cobro y la persistencia.

El problema que la gente reporta no es la tarifa por hora: es la factura sorpresa. Alguien dejó su agente corriendo, se fue veinte minutos y volvió a una cuenta que no esperaba; en los foros circula el caso de un agente desbocado de 300 dólares.

Apunte · precios

Los números por hora son parecidos entre proveedores. Lo que cambia la factura es si el reloj sigue corriendo mientras el sandbox está levantado sin hacer nada, que en un agente pasa seguido.

En pantalla

El mismo trabajo con el reloj partido en dos. La proporción que salga aquí es la que hay que llevarse, medida en vivo.

Apunte · Code Mode

Los modelos escriben mejor código del que improvisan cadenas de llamadas, porque programar es exactamente lo que vieron millones de veces en entrenamiento. Code Mode aprovecha eso.

En pantalla

Las mismas herramientas que ya tienes como MCP, expuestas como una API que el modelo puede orquestar en una sola pasada.

Apunte · EasyBits

Es el sandbox sobre el que está construido el taller. Las tres puertas importan porque no todos los equipos integran igual: unos quieren HTTP, otros el SDK dentro del código, y otros que el agente lo tome como herramienta.
